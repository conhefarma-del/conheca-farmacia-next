## Resumo Executivo

**Sobre o scope do audit:** admin (`/{lang}/admin/`) **não é página pública e não precisa de SEO** — é autenticada e protegida por RLS. RLS no Supabase isola dados. Os gaps abaixo afectam **conteúdo público** indexável (homepage, list pages, detail pages de artigos/eventos/lives, unsubscribe, etc.).

> **Gap 2 (robots) e Gap 3 (filter archived) não são "admin precisa de SEO"** — são hygiene de SEO público (conteúdo arquivado acessível por URL directa) e hygiene defensivo (bots mal-comportados). Mantidos no audit por causarem impacto público, mas com justificação corrigida.

## 🔴 Gaps Críticos (3)

### Gap 1 — Google Fonts via `<link>` (LCP + CLS penalty)

**File:** `app/layout.js:43-46`

```js
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossOrigin="anonymous" />
<link href="https://fonts.googleapis.com/css2?family=...&display=swap" rel="stylesheet" />
```

**Problema:** Network round-trip para Google Fonts, sem self-host, sem ajuste automático de métricas de fallback. LCP e CLS penalty — official Next.js guidance (`/learn/seo/fonts`) recomenda `next/font/google` com `display: 'swap'` + `adjustFontFallback: true` (CLS ≈ 0).

**Fix:**
```js
// app/layout.js
import { Inter } from 'next/font/google'
const inter = Inter({ subsets: ['latin'], display: 'swap', adjustFontFallback: true, variable: '--font-inter' })
// Aplicar via className no <html> ou <body>
```

**Prioridade:** Alta. **Esforço:** 1-2h (incl. propagação da CSS var nos componentes).

### Gap 2 — `robots.js` não bloqueia `/{lang}/admin/`

> **Nota:** admin é autenticado e não é página pública. RLS protege os dados. Este gap **não é sobre "admin precisar de SEO"** — é hygiene defensiva. `robots.txt` é uma boa prática de segurança/poluição do índice Google: bots mal-comportados (não Google) podem seguir links internos de newsletters/audit logs/admin emails e indexar `/{lang}/admin/login` ou paths com tokens temporários (CSRF, magic links, password reset). `Disallow` impede isso.

**File:** `app/robots.js:8-9`

```js
rules: { userAgent: '*', allow: '/', disallow: ['/admin/', '/api/'] }
```

**Problema:** Robots spec usa prefix match. `/admin/` matches `/admin/foo` mas **não** matches `/pt/admin/` ou `/en/admin/`. Como o proxy injecta `/{lang}/` em todas as rotas, admin vive em `/pt/admin/`, `/en/admin/`. Bots bem-comportados (Google) seguem robots; bots agressivos (scrapers, link-checkers) podem ignorar.

**Fix:**
```js
disallow: ['/admin/', '/pt/admin/', '/en/admin/', '/api/', '/pt/api/', '/en/api/'],
// OU wildcard (Yandex suporta):
// disallow: ['/[a-z]{2}/admin/', '/api/']
```

**Prioridade:** Média (boa prática de hygiene, não é SEO crítico). **Esforço:** 5min.

### Gap 3 — `is_archived` não filtra `generateStaticParams` nem `sitemap.js`

> **Nota:** Isto **não é sobre "admin precisar de SEO"** — é sobre conteúdo público arquivado. Após Phase 3 do admin role UI (commits 7ebe807, d70455c, bcfa498), admin pode arquivar artigos/eventos/lives. O **público** continua a poder aceder a estes conteúdos por URL directa (ex: `/pt/artigos/foo` antigo aparece em cache do Google, backlink externo, ou partilha em redes sociais). Como `is_archived` é filtro "soft" (não é `noindex` + não é 410), o conteúdo arquivado continua servível ao público, mas **deixou de aparecer nos feeds/lists** (público filtra por defeito).

**Files:**
- `app/[lang]/(public)/{artigos,articles,eventos,events,lives}/[slug]/page.js` (5 ficheiros)
- `app/sitemap.js:48, 76, 114`

**Problema:**
- `generateStaticParams` cacheia TODOS os artigos/eventos/lives no build (não filtra archived)
- `sitemap.js` adiciona TODOS ao XML (não filtra archived)
- Detail pages individuais **podem servir arquivados** se a query não filtra (verificar)

Resultado: Google indexa URLs arquivadas, mantendo "ghost URLs" no índice mesmo quando o admin já as removeu das listagens.

**Fix (2 locais):**

```js
// generateStaticParams em cada [slug]/page.js
const { data: articles } = await supabase
  .from('articles')
  .select('slug')
  .eq('is_published', true)
  .eq('is_archived', false)  // ← ADICIONAR
  .eq('lang', lang)

return (articles || []).map((a) => ({ slug: a.slug }))
```

```js
// app/sitemap.js (3 queries, articles/events/lives)
.eq('is_archived', false)  // ← ADICIONAR em cada query
```

**Alternativa (mais correcta semanticamente):** se admin quer "remover do Google" de verdade, deveria:
1. Set `robots: { index: false, follow: false }` na detail page (via `generateMetadata`)
2. OU retornar `notFound()` se `is_archived === true`

O `is_archived` no filter é um **soft-hide** (conteúdo acessível mas escondido). O **hard-hide** requer `notFound()` ou `noindex`. Esta decisão é de design — confirmar com product owner.

**Prioridade:** Média (afecta SEO público, não admin). **Esforço:** 30min para o filter; decisão de design para `notFound()` vs `noindex`.

## 🟡 Gaps Médios (3)

### Gap 4 — Title sem `title.template`

**File:** `app/layout.js:8-11`

**Problema:** Title é string fixa. Detail pages sobrescrevem manualmente (e.g. `artigos/[slug]:71` faz `${title} — Conheça Farmácia`). Se uma detail page devolver só `title: "X"`, perde-se o sufixo. Inconsistência SERP.

**Fix:**
```js
// app/layout.js
title: {
  default: 'Conheça Farmácia — Portal de saúde',
  template: '%s | Conheça Farmácia',
},
```

Detail pages passam a devolver só o título sem sufixo.

**Prioridade:** Média. **Esforço:** 1h (refactor em ~16 ficheiros).

### Gap 5 — Bug isolado em `sobre/page.js:13` (typo hreflang)

**File:** `app/[lang]/(public)/sobre/page.js:13`

```js
alternates: { languages: { pt: '/pt/sobre', en: '/en/sobre' } }  // ❌ en aponta para /en/sobre (não existe)
```

**Problema:** `en` aponta para `/en/sobre` mas a página EN espelhada é `/en/about`. Google segue este link → 404 ou redirect para `/pt/sobre`. Bug clássico de copy-paste.

Comparação:
- `sobre/page.js:13` → `en: '/en/sobre'` ❌
- `about/page.js:12` → `en: '/en/about'` ✅ (correcto, simétrico)

**Fix:** trocar `en: '/en/sobre'` por `en: '/en/about'`.

**Prioridade:** Média. **Esforço:** 1min.

### Gap 6 — Logos em `<img>` raw (Header/MobileDrawer/Footer)

**Files:**
- `components/layout/Header.jsx:35`
- `components/layout/MobileDrawer.jsx:61`
- `components/layout/Footer.jsx:17`

**Problema:** `<img src="/logo/3.png" alt="Conheça Farmácia" />` sem `width`/`height`. LCP element da página (logo no header é first thing browser paints). 0 optimization (sem WebP/AVIF), 0 size hint (CLS quando imagem chega).

**Fix:**
```jsx
import Image from 'next/image'
<Image src="/logo/3.png" alt="Conheça Farmácia" width={120} height={40} priority />
```

`priority` no logo do Header (LCP). 3 ficheiros.

**Prioridade:** Média. **Esforço:** 30min.

**File:** `app/layout.js:50-56` — `<script dangerouslySetInnerHTML>` lê `localStorage` para dark mode antes de React hidratar. Necessário mas viola CSP. Verificar se CSP permite `'unsafe-inline'` em `script-src` em `vercel.json`/`next.config.mjs`. Esforço: 10min audit.

const lastmod = t?.updated_at || live.updated_at || live.data || live.date
