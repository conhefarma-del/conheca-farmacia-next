# Quiz — Plano de Implementação (2026-08-13, v1)

> Plano baseado na análise de viabilidade de 2026-08-13 (dados reais:
> 191 fármacos com farmacologia + perfil, 435 interações fármaco-fármaco,
> 319 alimento, 396 doença, 6 protocolos, 697 flashcards). O Quiz **não
> inventa conteúdo**: todas as perguntas, respostas e distratores vêm de
> valores reais da base de dados.

## Decisões a confirmar (respondidas em 2026-08-13)

| # | Pergunta | Opção escolhida |
|---|----------|-----------------|
| 1 | Estrutura | **Página-hub `/praticar`** com dois cartões — Quiz e Flashcards |
| 2 | Banco de perguntas | **Ambos** — reutilizar os 697 flashcards como MCQ **e** geração dedicada (farmacologia, interações, protocolos) |

## Arquitetura

- **Público:**
  - `/praticar` — **hub** com dois cartões grandes: **Quiz** ("Testa-te agora" → `/quiz`) e **Flashcards** ("Revisão espaçada" → `/flashcards`), cada um com descrição e CTA.
  - `/quiz` — seletor de modos: por **deck** (os 12 decks de flashcards), por **tipo** (Farmacologia, Interações, Protocolos), **modo rápido** (aleatório) + toggle **"Guardar progresso" / "Sem registo"**.
  - `/quiz/[slug]` — sessão MCQ: pergunta, 4 opções, feedback imediato com **explicação + fonte**, barra de progresso, pontuação final e botão "Repetir". `noindex` (sessão interativa).
- **Admin:** `/admin/quiz` — estatísticas de tentativas (total, média de acertos, por modo/deck). As perguntas de protocolo já têm admin próprio (`clinical_protocol_quizzes` no módulo de protocolos); as restantes são geradas (sem tabela de conteúdo).
- **Dados:** 1 tabela nova — `quiz_attempts` — padrão RLS do projeto. **Sem tabela de perguntas**: as sessões são construídas em tempo real a partir dos dados existentes (`flashcards`, `drug_pharmacology`, `drug_interactions`, `clinical_protocol_quizzes`).
- **Conteúdo — 4 fontes, 100% reais:**
  1. **Flashcards (697)** — pergunta = `front_pt`, resposta = `back_pt`; distratores = versos de outros cartões do mesmo deck (idealmente do mesmo `card_type`, para opções de comprimento semelhante).
  2. **Farmacologia (191)** — "Qual o mecanismo de ação de X?", "A que classe pertence X?", "Qual a meia-vida de X?" (`mechanism_pt`, `class_pt`, `half_life_pt`); distratores = valor real do mesmo campo noutros fármacos do mesmo grupo ATC.
  3. **Interações (435 + 319 + 396)** — "Que grau tem a interação A + B?" (`severity`); distratores = outros graus reais do dataset.
  4. **Protocolos** — as perguntas já curadas e publicadas de `clinical_protocol_quizzes` (4 opções + `correct_index` + explicação) entram diretamente; complemento opcional: "Qual a dose de X no protocolo Y?" a partir do JSONB `drugs` dos steps.
- **Progresso:** `quiz_attempts.user_id` (nullable). Com sessão anónima → guarda a tentativa; modo "sem registo" → não insere, pontuação apenas na UI (localStorage opcional só para ver o último resultado).

## Simplificação da linguagem (sem inventar conteúdo)

As perguntas usam termos clínicos reais, mas **sempre que possível** são
reescritas numa linguagem mais acessível — sem abdicar dos termos clínicos
essenciais nem alterar o significado dos factos. Regras:

1. **Os dados-fonte não mudam** (`drug_pharmacology`, `class_pt`, versos dos
   flashcards...). A simplificação aplica-se **apenas à apresentação** da
   pergunta e das opções no Quiz. As respostas corretas e a explicação citam
   o texto clínico real + fonte.
2. **Mapa de sinónimos curado** (`lib/quiz/simplify.js`, por língua) — só
   equivalências seguras e bem conhecidas; termos sem sinónimo seguro ficam
   como estão (a parte do "quando possível"):
   - "fármaco" → "medicamento"
   - "mecanismo de ação" → "como atua"
   - "classe farmacológica" → "grupo de medicamentos"
   - "anti-inflamatório não esteroide (AINE)" → mantém-se, com glossário
   - "meia-vida" → mantém-se, com glossário entre parênteses
3. **Templates de pergunta mais simples** — "Qual é o mecanismo de ação de X?"
   → "Como atua o X no organismo?"; "A que classe pertence X?" → "A que
   grupo de medicamentos pertence o X?"
4. **Gloss entre parênteses** para o termo clínico que se mantém:
   "Qual a meia-vida (tempo até metade do fármaco sair do organismo) de X?"
   — preserva a literacia clínica e acrescenta acessibilidade.
5. **Conservadorismo clínico:** a simplificação nunca troca um termo por outro
   com significado diferente (ex.: "meia-vida" ≠ "duração de ação"). O mapa
   é revisto editorialmente e coberto por testes.

Exemplo prático (pergunta de farmacologia):

| Original (dado real) | Quiz (apresentação simplificada) |
|---|---|
| "Qual é o mecanismo de ação do Ibuprofeno?" | "Como atua o Ibuprofeno no organismo?" |
| "A que classe farmacológica pertence o Ibuprofeno?" | "A que grupo de medicamentos pertence o Ibuprofeno?" |
| "Qual a meia-vida do Ibuprofeno?" | "Qual a meia-vida (tempo até metade do fármaco sair do organismo) do Ibuprofeno?" |

## Migração 158 — Schema

**Ficheiro:** `supabase/migrations/158_quiz_attempts.sql`

```sql
-- Tentativas de quiz (histórico) — user_id NULL = modo "sem registo" (não insere)
CREATE TABLE IF NOT EXISTS public.quiz_attempts (
  id           UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id      UUID REFERENCES auth.users(id) ON DELETE CASCADE,  -- NULL = efémero
  mode         TEXT NOT NULL,        -- 'deck' | 'tipo' | 'rapido'
  deck_id      UUID REFERENCES public.flashcard_decks(id) ON DELETE SET NULL,
  question_source TEXT NOT NULL,     -- 'flashcard' | 'pharmacology' | 'interaction' | 'protocol'
  total        INTEGER NOT NULL DEFAULT 0,
  correct      INTEGER NOT NULL DEFAULT 0,
  details      JSONB NOT NULL DEFAULT '[]',  -- [{question_id, correct(bool), time_ms}] p/ análise
  started_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at  TIMESTAMPTZ,
  created_at   TIMESTAMPTZ DEFAULT now()
);

-- RLS (padrão do projeto)
ALTER TABLE public.quiz_attempts ENABLE ROW LEVEL SECURITY;

-- Cada utilizador vê/altera apenas as suas tentativas
CREATE POLICY "own_attempts_select" ON public.quiz_attempts
  FOR SELECT TO authenticated USING (user_id = auth.uid());
CREATE POLICY "own_attempts_insert" ON public.quiz_attempts
  FOR INSERT TO authenticated WITH CHECK (user_id = auth.uid());
CREATE POLICY "own_attempts_update" ON public.quiz_attempts
  FOR UPDATE TO authenticated USING (user_id = auth.uid()) WITH CHECK (user_id = auth.uid());
CREATE POLICY "own_attempts_delete" ON public.quiz_attempts
  FOR DELETE TO authenticated USING (user_id = auth.uid());

-- Admin: tudo
CREATE POLICY "admin_all_quiz_attempts" ON public.quiz_attempts
  FOR ALL TO authenticated
  USING (EXISTS (SELECT 1 FROM public.admin_users WHERE admin_users.user_id = auth.uid()));

-- Índices
CREATE INDEX idx_quiz_attempts_user ON public.quiz_attempts(user_id, created_at DESC);
CREATE INDEX idx_quiz_attempts_source ON public.quiz_attempts(question_source);
```

> Nota: **não** há tabela de perguntas — as sessões são montadas em tempo real
> pelo engine (T2) a partir das tabelas existentes. Se no futuro se quiser
> curadoria manual de perguntas gerais, cria-se uma `quiz_questions` override
> (fora de âmbito da v1).

## Tarefas

### T1 — Migração 158 (schema)
SQL acima. Aplicar no Supabase.

### T2 — Engine puro: `lib/quiz/engine.js` + `lib/quiz/simplify.js` (novos) + testes
Funções puras, sem I/O (como `lib/flashcards/sm2.js`):
```js
export function shuffle(arr, rng = Math.random)          // embaralha opções
export function buildFlashcardQuestion(card, pool)        // front → [back + 3 versos do pool]
export function buildPharmacologyQuestion(drug, field, pool) // campo real + distratores reais
export function buildInteractionQuestion(interaction, drugNames, severityPool)
export function buildProtocolQuestion(pq)                 // usa clinical_protocol_quizzes (4 opções + correct_index)
export function buildSession(questions, count)            // seleciona N, monta {question, options, correctIndex, source, explanation}
export function score(answers)                            // { correct, total, pct }
```
- `lib/quiz/simplify.js` (**já existe**): `buildFront(cardType, names, lang)` (templates de pergunta simplificados `FRONT_TEMPLATES`) e `simplifyText(text, lang)` (mapa de sinónimos conservador). Aplicam-se às **perguntas e opções apenas** (nunca à resposta correta/fonte); chaves i18n `quiz_simplify.*` por língua se forem precisas entradas editáveis.
- Garantia de segurança: **sem distrator repetido**, resposta correta sempre presente, opções embaralhadas.
- Testes unitários (node): embaralhar com semente, distratores únicos, `correctIndex` bate com a resposta real, nenhum texto inventado (asserts contra os dados de entrada), e a simplificação **nunca altera a resposta correta nem a fonte**.

### T3 — Camada de dados: `lib/api/quiz.js` (novo)
- `getQuizPools()` — para montar sessões: decks + cartões publicados (por deck e `card_type`), farmacologia publicada (mecanismo/classe/meia-vida por fármaco), interações publicadas (com nomes resolvidos), `clinical_protocol_quizzes` publicados.
- `getQuizStats()` — estatísticas agregadas para o admin (totais, média de acerto, por modo).
- Padrão `unstable_cache` + tags `quiz`; queries com colunas explícitas; apenas registos `published` e `is_archived = false`.

### T4 — Ações server: `lib/actions/quiz.js` (novo)
- `startQuiz({ mode, deckSlug?, source?, count? })` — `requireAuth` opcional (funciona sem sessão para o modo "sem registo"); monta a sessão via engine (fetch dos pools → `buildSession`); devolve perguntas **sem** revelar a correta (o `correctIndex` fica no servidor para a resposta ser validada).
- `answerQuiz(questionId, selectedIndex)` — valida a resposta contra o dado real no servidor (nunca confia no cliente); devolve `{ correct, correctAnswer, explanation, source }`.
- `finishQuiz({ mode, deckSlug?, source?, total, correct, details })` — guarda em `quiz_attempts` **apenas** se houver sessão anónima (`requireAuth`); modo "sem registo" simplesmente não insere.
- Admin: `getQuizStatsAction` — `requireAdmin` + `getQuizStats`.

### T5 — Admin: `app/[lang]/admin/(protected)/quiz/page.js`
- `components/admin/QuizStatsPage.jsx` (novo): cards com total de tentativas, média de acerto, tentativas por modo/fonte; tabela recente (sem `details` para não pesar).
- Sidebar: item "Quiz" (ícone `ListChecks`/`BrainCircuit`).
- As perguntas de protocolo continuam a ser geridas em `/admin/protocolos` (módulo existente).

### T6 — Páginas públicas
